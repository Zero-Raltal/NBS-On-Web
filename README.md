# Note Block Studio — 网页重制版

用 **HTML + 原生 JavaScript**（无框架、无构建步骤）重制的 [Minecraft Note Block Studio](https://github.com/OpenNBS/NoteBlockStudio)。
界面布局、操作方式、`.nbs` 文件格式都对齐桌面版 3.11.0，全部绘制逻辑与数据操作是照着 GML 源码（`control_draw()`、`open_song_nbs()`、`save_song()`、`selection_*`、`macro_*` 等）逐段移植的。

> 作者：ZeroRaltal · 以 MIT License 开源

## 在线使用

直接用浏览器打开仓库根目录的单文件版即可，无需服务器、无需安装：

- **<https://zero-raltal.github.io/NBS-On-Web/>** —— 单文件压缩版（HTML/CSS/JS 全部内联并压缩，
  所有素材以 LZ77 + base91 编码内嵌，打开即用；也可下载到本地双击打开，功能完全一致）

根目录的 `noteblockstudio.html` 是同一内容的**未压缩可读版**，只用于调试（体积大，别当入口用）。

### 为什么入口是单文件版，而不是源码版

源码版（`src/index.html`）需要加载 21 个 JS 文件 + 88 个素材文件，冷缓存下实测：

| 入口 | 请求数 | 就绪耗时（冷缓存） | 就绪耗时（热缓存） |
|---|---|---|---|
| 源码版 `src/index.html` | 114 | **约 132 秒** | 约 0.3 秒 |
| 单文件版根 `index.html` | 1 | **约 6 秒** | 约 0.2 秒 |

差距的来源不是体积（两者传输量接近，约 700KB），而是 **GitHub Pages 上 114 个并发请求的
排队与连接开销**。所以默认入口用单文件版，源码版保留在 `src/` 供阅读和改代码。
如果你只是要看/用，永远用根目录那个。

## 从源码运行

源码在 `src/`。浏览器出于安全限制不能直接读本地文件，需要一个静态服务器：

```bash
cd src
python -m http.server 8123
# 然后访问 http://localhost:8123/index.html
```

用 Chrome / Edge / Firefox 打开即可，无需安装。本地服务没有 Pages 的网络延迟，
源码版在这个场景下很快就绪。

## 从 cbnote 导入

[cbnote](https://github.com/Zero-Raltal/MCBE-CBNoteBlock) 是同一作者的 MCBE 指令音乐工具，
本仓库支持它导出的两种格式：

**`.cbnd`（推荐）**：位流格式，含速度（t/s）与循环标记，信息最完整，导入后即刻可播放。

**指令 `.txt`**：解析 `execute … run playsound …` 反推音符。为了兼容各家生成器的输出，
解析时**只认 `execute` 指令块**，其余内容一律忽略，并对常见干扰做统一清洗：

**只认 execute 块**（这是兼容性的关键）

- 表头、歌名、作者、时间戳、分隔线、说明文字、纯注释 —— 全部忽略，不做任何猜测
- `setblock` / `scoreboard` / `fill` 等非 `execute` 指令 —— 忽略
- `execute` 但内容不是 `playsound`（如循环跳转） —— 忽略
- 判定依据是 `execute` 作为**命令起始词**出现且后面紧跟合法的子命令关键字
  （`as` / `at` / `run` / `if` / `unless` …），所以说明文字里出现的 "execute" 不会被误判
- 日志类导出常见的前缀（`[12:34:56] `、`1. `）自动丢弃
- 续行拼接导致两条指令粘在一行时，按 `execute` 起点重新切开

**注释一律忽略**

| 干扰 | 处理 |
|---|---|
| CRLF / CR / LF 混用 | 统一换行 |
| 行尾续行反斜杠 `\` | 与后续行拼接（允许中间夹空行） |
| 行首 `/` 或 `\`（含 `//`、全角 `／`） | 去掉（正文里的 `/` 不动，如 `minecraft:block/note_block`） |
| 行尾 `// …` 或 `# …` | 当作注释切掉 |
| 零宽空格 / BOM / 不间断空格 | 清除 |
| 全角括号、逗号、等号、花括号 | 转半角 |
| 中文 `【】` | 按上下文判断转 `{}` 还是 `[]` |
| 成对引号（含 `“”‘’`） | 删除 |
| 制表符 / 多余空格 | 归并为单空格 |

**按乐器分组落层**

`.cbnd` 与指令 txt 导入都按乐器分组，做法与 MIDI 导入一致（`midi.js:186-207`）：

- 每种乐器占一段**连续层带**，层带起点 = 前面所有乐器高度之和
- 层带高度 = 该乐器在同一刻的最大同时音符数
- 放置时只在自己的层带内找空位，**不会跨到别的音色的层**
- 层名写成乐器名（`Harp` / `Bass Drum` / `Pling` …），图层面板一眼可辨
- 同刻、同乐器、同音高重复出现时只保留一个

解析规则：

- 音色取 `playsound` 后的第一个参数，`note.harp` / `minecraft:block.note_block.harp` 均可
- 音高 `pitch` 反解：`key = 54 + 12 × log₂(pitch)`，得到的是 **cbnote / Minecraft 的编号**，
  还需**减去 9** 才是本编辑器的 key（见下方「key 编号换算」）
- 刻位支持两种写法：
  - 显式刻 `execute as @a[scores={t=5}]` → 第 4 刻
  - 取反式 `execute as @a[scores={t=-1..}] … unless entity @s[scores={t=!1,t=!3}]` → 第 0、2 刻
    （`!` 后面列出的就是发声刻，这是基岩版选择器与 `unless` 形成的双重否定）
- 音量 `volume` 映射为方块音量（0–1 → 0–100）
- **速度无法从 txt 还原**（指令按刻编号，每刻实际时长取决于循环装置），
  导入后按 **20 t/s** 处理 —— 这是「不设延迟的循环命令方块」的速度（游戏刻固定 20 Hz），
  也是这类 txt 最常见的生成方式。若要别的速度，导入后在左上角速度框调整即可

### key 编号换算（重要）

cbnote / Minecraft 与本编辑器用的是**两套不同的 key 编号**，直接混用会整体高 9 个半音：

| | 公式 | 1.0 播放速率对应的 key | 该 key 的音名 |
|---|---|---|---|
| cbnote / Minecraft | `pitch = 2^((key−54)/12)` | **54** | F#4 |
| 本编辑器（NBS 语义） | `rate = 0.5 × 2^((key + ins.key − 78)/12)`，`ins.key = 45` | **45** | F#4 |

两者指向同一个音（F#4），但编号相差 **9**。所以两侧换算关系是：

```
本编辑器 key = cbnote key − 9
cbnote key   = 本编辑器 key + 9
```

`.cbnd` 与指令 `.txt` 两条导入路径都会做这个换算。换算后若超出本编辑器的音域
（0–87），会被夹到最近的端点，并提示「有 N 个音超出音域」。

> 这一条是修 bug 时补上的：此前按「两侧都以 C4 = 54 为 1.0」的错误假设直接沿用编号，
> 导致导入后音高整体偏高一个小六度，与 cbnote 和游戏内都不一致。

## 与源码的有意差异

移植过程中发现以下几处源码行为在浏览器里会造成明显问题，做了最小改动并在代码里就地注释说明：

1. **`draw_sprite` 越界帧**：GameMaker 对超出 `image_number` 的子图序号取模回绕（不是"不画"、也不是夹取）。`core.js` 的 `frame()` 按取模实现，否则导出对话框的宣传图会整块消失。
2. **播放标记竖线叠放次序**：源码先画三角后画竖线，线正好压在三角正中。这里改成先画线后画三角，几何位置完全一致，只是避免线在三角上切一刀。
3. **`note_offset` 取样源**：源码用 `frac(marker_pos)`，前提是 `starta` 与 `marker_pos` 整数相位一致。浏览器里 `starta` 会被 `median` 夹取、累积浮点误差，相位一旦错开，按帧跟随会出现「每前进一刻画面被拉回一格」。改为 `frac(starta)` 并用 `floor` 取整（而非四舍五入），保证 `note_offset ∈ [0,31]`、进位只由 `floor(starta)` 承担。
4. **时间轴基准**：按刻/按页模式用 `floor(starta)`、按帧模式用连续 `starta`，且都不再额外减 `note_offset`（`xx` 式已含小数），否则小数被计算两次。

## 已知缺口

- 音频导出目前只支持 WAV（16 位 PCM 立体声）。MP3 / OGG 需要额外的编码器，未接入。
- MIDI 输入设备依赖浏览器 Web MIDI API：Chrome / Edge 支持，Firefox / Safari 默认不支持；
  且必须通过 http(s) 打开（`file://` 无法授予 MIDI 权限），所以单文件版直接双击打开时该功能不可用。
  权限请求带 12 秒超时，超时后会显示具体原因并提供「重试」，不会一直卡在请求中。

## 音频导出是怎么做的

不用 `OfflineAudioContext` 搭音频图，而是**自己混音**：

- 每个音色按「音高 + 采样率」预先重采样并缓存，同音高复用
- 把所有音符的波形直接累加进左右声道 `Float32Array`
- 等功率声像、tanh 软限幅（防多音叠加削波）
- 分段编码成 16 位 PCM 立体声 WAV

**为什么不用 `OfflineAudioContext`**：最初就是那么写的，功能正确，但每个音符都是一个
`BufferSource` 节点，几千个节点连到同一条链上时混音开销急剧增长。实测 120 秒音频 /
4800 个音符需要 3 分钟以上，用户看到的就是「点了导出很久没反应」。改成手动混音后
同样的内容约 1.7 秒（约 **70 倍实时**）。

导出期间左下角显示实时进度条与百分比（不是一闪而过的提示），长时间渲染也能看到进展。

## 后台播放为什么不会变慢

浏览器最小化时 rAF 完全停摆、`setInterval` 被降频。早期实现靠「每帧 `marker_pos += tempo * dt`」，
而 `dt` 上限卡在 0.5 秒，于是 1 秒真实时间只推进 0.5 秒播放 —— 最小化后速度恰好减半。

现在的做法：

1. **时间基准改用 Web Audio 的 `ctx.currentTime`**。这个时钟由音频硬件驱动，后台不降频、
   不受 rAF/定时器影响。播放位置 = 锚点位置 + (音频时钟 − 锚点时钟) × tempo。
2. **提前排期**。不是「标记走到哪列才播哪列」，而是把未来一小段时间内的音符按精确时刻
   `start(when)` 交给音频引擎。窗口前台 0.25 秒、后台自动拉到 1.5 秒，
   即使回调被降频到 1 次/秒，音符也一个不漏。

实测（真实窗口最小化 5 秒，tempo=10）：墙钟推进 5.02 秒、音频时钟推进 5.02 秒、
位置推进 48.79 格 → **9.72 t/s**，排期列连续无空洞（旧行为约 5 t/s 且大量漏音）。

### 暂停时必须撤销已排期的音符

提前排期有一个必须配套处理的地方：**暂停/跳转要把「已经交给音频引擎、但还没开始响」的音符撤掉**。

不做这一步会出现两个看起来很奇怪的现象：

- 点了暂停，声音还继续往外冒一小段（最长等于前瞻窗口）
- 进度线明明还停在某个音符前面，暂停后它却响了 —— 因为那个音早就被排进了未来时刻

实现上，每个 voice 记录自己的起播时刻 `startAt`，`audioCancelScheduled()` 只撤销
`startAt > now` 的那些。**正在响的音不动**，保持自然衰减 —— 这与原版 GML 的语义一致：
`toggle_playing` 暂停时只是不再投递新音符，全程没有调用过 `audio_stop_all`，
所以硬切反而会多出一声不自然的断音。

调用点：暂停、停止按钮、回车归零、拖动播放标记、点击时间轴跳转、循环回绕、
播放到曲尾/区间末自然结束。

## 触屏与竖屏

### 怎么判断「这是不是触屏设备」

不能只看 UA，也不能只做一次性能力检测：iPadOS 13+ 桌面模式 UA 里写的是
`Macintosh`；手机可能接着蓝牙鼠标；触屏笔记本平时用触控板。所以把
**能力**和**当前模态**拆成两件事：

| 字段 | 含义 | 判据 |
|---|---|---|
| `TOUCH.capable` | 设备是否**具备**触屏能力 | `maxTouchPoints > 0` 或 `pointer: coarse` 或 `'ontouchstart' in window`，三者取并集 |
| `TOUCH.mode` | 用户**此刻在用**哪种输入 | 跟随最近一次真实指针事件的 `pointerType`：`touch`/`pen` → 1，`mouse` → 0 |

初始模态用「主指针粗糙**且**确有触点」猜一次，之后完全跟随实际交互。
于是手机接上鼠标就会切回鼠标语义，触屏笔记本手点屏幕就切到触屏语义。
指针处理器**无条件安装** —— 漏装的风险（长按/拖动全失效且用户无法自救）
远大于多装（对 `pointerType === 'mouse'` 立刻返回）。

**触屏模态不改动全局缩放。** 早期版本为了放大可点面积，在触屏模态下把有效缩放
强制抬到 1.3（`TOUCH_MIN_SCALE`），结果「一切到触屏模式整个页面突然放大」——
用户设的 100% 被静默改成 130%，而用户既不知道发生了什么、也不好从别处调回来。
缩放是用户的偏好，不该被改写，所以这个下限已经移除。
触控目标偏小的问题改由各控件自己的尺寸解决（抽屉按钮 24~26 逻辑像素、琴键 39）。
绘制变换与输入换算仍然共用 `touchEffScale()`，否则"画到哪儿就点不到哪儿"。

### 长按 = 右键

原版右键在网格上的语义很具体：按下若有音符就删掉，松开时若没移动也没删到
东西就弹菜单。而左键是**松开时**才落音符。利用这个时序：

1. 按下时先照常投递左键（按钮要即点即应）；
2. 长按 450ms 到点时，**撤回左键但不投递 `mbr[0]`** —— 不落音符；
3. 同时投递一个真正的 `mbp[2]`，右键逻辑原样复用；
4. 抬手投递 `mbr[2]`，菜单弹出。

长按触发后把落点**冻结**，后续移动不再投递 —— 否则手指微动会被判成
「右键拖动擦除」，刷掉一片音符（桌面端右键拖动仍是连续擦除，这是刻意偏离）。

### 竖屏布局（按实时宽高比，不是按设备）

`S.portrait = (rh >= rw * 1.15)`，每帧重算，转动窗口立刻切换。
阈值取 1.15 而非 1.0：方块状窗口按桌面布局更舒服。

竖屏下宽度最稀缺 —— 桌面版图层面板固定吃掉 270 逻辑像素，手机总共才 300 左右，
网格只剩一两列。所以：

- **网格吃满整个宽度**（`x1 = -2`），图层面板与钢琴都不再参与布局计算；
- **顶栏自动折行**：竖屏宽度放不下约 30 个图标，整行会溢出到屏幕外。
  改成「下一个放不下就换行」，行高 25；`drawTopBar` 把实测高度写回
  `S.toolbar_h`，`computeLayout` 据此把网格往下推；
- **底部抽屉**：`图层 / 琴键 / 属性` 三个标签，浮层抽出、互斥、带暗色遮罩，
  抽屉外点击即收起；
- 抽屉打开时 `drawerOpen()` 参与 `blocked` 判定，屏蔽下层网格点击。

两个容易踩的坑（都已修）：

- 竖屏的纵向预算必须**从 `y1` 倒推**，不能沿用桌面的固定 `rhval`。顶栏高度是浮动的，
  再按固定值从 `rh` 往回留，网格底部会算到屏幕外，横向滚动条和抽屉标签条互相压住。
- `drawInfoBoxes`（时间/小节/速度）与 `drawCompatibility`（兼容性图标）都硬编码在
  固定坐标。竖屏下前者整体下移到折行工具条之后，后者省掉文字只留图标贴到标签行右侧。

### 单指拖动平移

触摸在网格上拖动可平移视图。两个实现要点：

- `drawHScrollbar` 每帧 `return round(SB.val[0])` 再写回 `S.starta`，也就是说
  `starta` 每帧被取整一次。手指每移动一点只有 0.4~0.5 格，取整后回到 0 ——
  直接写 `starta` 会「拖了完全没反应」。所以平移量先累积在 `TOUCH.pan_acc`，
  只把整数部分写入，余数留到下次。
- `handlePlayback` 里「跟随播放位置自动居中」**任何时候都在执行**（不只是播放中），
  `marker_follow` 默认就是 1，每帧都会把 `starta` 强行设成标记居中值。
  平移期间临时关掉 `marker_follow`，松手恢复。

### 抽屉是浮层，必须看到真实输入

`drawerOpen()` 让 `blocked` 为真，而 `editorFrame` 在 `blocked` 时会先清空
`G.mb / G.mbp / G.mbr`，再调用 `drawEditor`。抽屉在 `drawEditor` 之后才绘制，
于是它内部所有读 `G.mb` 的控件（琴键、按钮、名字输入框）**永远收不到按下** ——
这正是「抽屉里的钢琴点不动、音轨按钮失效」的原因。

修法是：抽屉绘制期间把 `UI.rawMb / rawMbp / rawMbr`（清零前的快照）换进 `G`，
画完再换回去。同时给 `editorFrame` 补上 `UI.rawMb`（原先只存了 `rawMbr`、`rawMbp`）。

另外注意标签条那一层：写成裸的 `if (G.mbr[0])` 而不做命中测试，
同一次抬手会把循环里**每一个**标签都执行一遍，最后留下最后一个 ——
表现就是「点哪个标签都跳到属性抽屉」。

### 音轨（图层）抽屉复用桌面版的图标

抽屉里的七个按钮直接调桌面版同一个 `layerIcon()`，它内部已按主题分派：
theme 0/1 用 `spr_frame4` 底板 + `spr_layericons`；theme 2 同款但图标取白；
theme 3 用 `spr_layericons_f` 双层（基帧 + accent 上色层）。
所以抽屉按钮和桌面版图层面板长得一模一样，也自动跟着换主题，不需要另画一套。

三个曾经失效的功能（都已按桌面版语义对齐）：

- **锁定 / 独奏不是两个独立布尔**，而是同一个字段 `S.layerlock` 的三态：
  `0` 正常、`1` 静音、`2` 独奏，且独奏还要同时维护 `S.solostr`（形如 `|3|7|`）。
  写成两个独立开关会导致「点了独奏，该层反而被静音」。
- **新建层用 `addLayer(layer)`**，不是 `addLayer(layer + 1)` —— `addLayer` 自己会把
  新层插在 index 位置并后移原有内容。
- 删除 / 新建 / 上下移之前都要 `S.playing = 0`，否则播放中改结构会让排期游标
  指向已不存在的层。

### 八度箭头的跨度

`S.startkey` 是**白键索引**（0 = A0），不是半音数 —— 色度键号是 `startkey + sharpkeys`。
直接把半音增量加到 `startkey` 上，一次 +6 会变成跨 7 个白键 ≈ 11 个半音，
实测「按一下从 C4 跳到 B4」，几乎整个八度，这就是跨度太大的原因。

现在先在**半音域**算出目标键号，再用 `chromaToWhite()` 换算回白键索引；
步长 `OCT_STEP = 6`（三全音），目标落在黑键时向下吸附到相邻白键
（键盘无法从黑键起画，所以相邻两次步进会在 5~7 半音之间交替，平均 6）。
抽屉底部还会显示当前实际音域（如 `C4 ~ D5`），让"跳到哪了"一眼可见。

## 单文件版是怎么做的

根目录的 `index.html` 是 `src/` 的完整内联版本：

- 所有 JS / CSS 合并进一个 `<script>` / `<style>`
- `src/assets/` 下的图集与音色（88 个文件）先用 **LZ77** 压缩，再用 **base91** 编码成纯文本嵌入
- 页面内置 LZ77 解码器与 base91 解码器，并在 `fetch` 层做了内存文件系统垫片，所以 `assets/...` 路径照常可用、无需改动业务代码
- favicon 以 data URI 内联，因此「下载到本地双击打开」时标签页图标也不会丢
- base91 字母表刻意排除了 `<`，因此数据块可以放进裸 `<script>` 而不需要任何转义

它也彻底消除了那 114 个请求：页面只下一个文件，素材全部从内存读取。
冷缓存首次打开因此从约 132 秒降到约 6 秒。

原始素材 425 KB → LZ77 后 380 KB（89.3%）→ base91 后 466 K 字符；整个单文件 716 KB。
